MÓDULO 1: GESTÃO DE ACESSO E USUÁRIOS
--------------------------------------------------------------------------------

FUNCIONALIDADE 1.1: AUTENTICAÇÃO DE USUÁRIOS
Escopo: Permitir que qualquer pessoa entre no sistema usando número de telefone moçambicano e PIN pessoal.
Detalhes:
- Login obrigatório com formato +258 seguido de 9 dígitos. Sistema valida formato antes de aceitar.
- PIN de 4 a 6 dígitos criado pelo próprio usuário no primeiro acesso.
- Sistema mantém sessão ativa para não deslogar toda hora.
- Opção "Esqueci PIN" onde organizador ou admin reseta para o usuário.
- Logout encerra sessão em todos dispositivos.
- Bloqueio temporário após 5 tentativas erradas de PIN para evitar brute force.

FUNCIONALIDADE 1.2: GESTÃO DE PERFIS DE USUÁRIO
Escopo: Sistema reconhece 5 tipos de pessoa com permissões diferentes.
Detalhes:
- Admin Global: Dono da plataforma SaaS. Vê todas organizações, métricas de negócio, pode suspender grupos.
- Organizador: Dono de um grupo de xitique. Controle total sobre seus collectors, clientes, dinheiro, empréstimos.
- Collector: Funcionário que coleta. Só vê e edita clientes atribuídos a ele. Não vê dados de outros collectors.
- Ticante/Cliente: Pessoa que poupa. Só acessa próprio cartão, extrato, saldo, dívida. Não vê nada de outros.
- Auditor: Fiscal. Acesso total para leitura, zero permissão de edição. Entra com período limitado definido pelo organizador.
- Um usuário pode ter perfis diferentes em organizações diferentes. Ex: João é Collector na Org A e Ticante na Org B.

FUNCIONALIDADE 1.3: GESTÃO DE ORGANIZAÇÕES
Escopo: Cada grupo de xitique é uma organização isolada.
Detalhes:
- Criar organização com nome do grupo, ex: "Xitique Bairro Central".
- Definir dono/organizador principal.
- Convidar membros por número de telefone, sistema envia convite.
- Configurações por organização: limite de dias retroativos, taxa de juros padrão, regras customizadas.
- Dados de uma organização nunca vazam para outra. Isolamento total.

MÓDULO 2: GESTÃO DE CLIENTES E CICLOS DE POUPANÇA
--------------------------------------------------------------------------------

FUNCIONALIDADE 2.1: CADASTRO DE CLIENTES/TICANTES
Escopo: Registrar pessoas que participam do xitique.
Detalhes:
- Dados: nome completo, telefone +258, taxa diária em MZN que cliente se compromete a poupar.
- Vincular cliente a um collector responsável pela coleta.
- Vincular cliente a uma organização.
- Ativar/desativar cliente sem apagar histórico.
- Busca por nome ou telefone.
- Cliente pode estar em múltiplas organizações com taxas diferentes.

FUNCIONALIDADE 2.2: CICLO DE POUPANÇA DE 30 DIAS
Escopo: Coração do xitique. Cada cliente tem um cartão digital de 30 dias por mês.
Detalhes:
- Todo dia 1 do mês sistema pode criar ciclo novo para cliente ativo.
- Ciclo tem 30 posições, dia 1 até dia 30.
- Cada dia tem 3 status possíveis: O=Aberto não pago, X=Marcado pago, P=Confirmado pago após fechamento.
- Taxa diária fixa por ciclo, ex: 500 MZN/dia.
- Calcular automaticamente: dias pagos, dias restantes, total poupado = dias_pagos x taxa_diaria.
- Calcular meta: total faltante = (30 - dias_pagos) x taxa_diaria.

FUNCIONALIDADE 2.3: MARCAÇÃO DE DEPÓSITO DIÁRIO
Escopo: Collector marca quando cliente pagou o dia.
Detalhes:
- Collector seleciona cliente, seleciona dia do mês, marca X.
- Sistema registra: quem marcou, quando marcou, de qual dispositivo, se estava online ou offline na hora.
- Se marcou offline, registra hora real e hora que sincronizou com servidor.
- Marcação é instantânea, sem delay.
- Collector só consegue marcar clientes atribuídos a ele.
- Não permite marcar dia futuro. Só hoje ou dias passados.

FUNCIONALIDADE 2.4: LANÇAMENTO RETROATIVO
Escopo: Permitir corrigir esquecimento ou pagamento atrasado.
Detalhes:
- Collector pode marcar dias anteriores ao dia atual.
- Limite padrão: até 7 dias para trás. Organizador pode configurar limite por organização.
- Se marcar 3 dias ou mais para trás, sistema obriga escrever motivo: "Cliente pagou atrasado", "Esqueci de marcar", etc.
- Sistema carimba transação como "retroativo" para auditoria.
- Se collector faz 3+ lançamentos retroativos em 7 dias, organizador recebe alerta automático.
- Organizador pode marcar qualquer dia do mês sem limite.

FUNCIONALIDADE 2.5: REVERSÃO DE DEPÓSITO
Escopo: Desfazer marcação errada.
Detalhes:
- Collector pode desfazer um X que marcou, voltando para O.
- Limite: até 24 horas após ter marcado. Depois disso só organizador consegue.
- Obrigatório informar motivo da reversão: "Marquei errado", "Cliente não pagou", etc.
- Sistema registra: quem reverteu, quando, motivo, qual era valor anterior.
- Histórico de reversão fica guardado para sempre, nunca apaga.
- Organizador pode reverter qualquer X a qualquer momento.

FUNCIONALIDADE 2.6: TRANSPORTE DE DIAS PARA MÊS SEGUINTE
Escopo: Flexibilidade para cliente que não completou 30 dias.
Detalhes:
- Ao fechar mês, se cliente tem menos de 30 dias pagos, organizador escolhe:
- Opção A - Multa: Cliente perde 1 dia do total, ciclo zera, mês seguinte começa do dia 1.
- Opção B - Transportar: Dias pagos viram crédito no mês seguinte. Ex: pagou 18 dias em Maio, Junho já começa com 18/30 marcados, só precisa pagar 12 dias para fechar.
- Sistema registra decisão para auditoria.
- Cliente vê no app que dias foram transportados.

MÓDULO 3: FECHAMENTO DIÁRIO E CONTROLE DE CAIXA
--------------------------------------------------------------------------------

FUNCIONALIDADE 3.1: FECHAMENTO DIÁRIO DO COLLECTOR
Escopo: Todo fim de dia collector declara quanto dinheiro tem em mãos.
Detalhes:
- Collector informa "Valor Contabilizado", ex: 12.500 MZN que contou fisicamente.
- Sistema calcula automaticamente "Total Sistema": soma de todos X que collector marcou no dia x taxa_diaria de cada cliente.
- Sistema compara: Diferença = Valor Contabilizado - Total Sistema.
- Se diferença = 0, fechamento verde "OK".
- Se diferença negativa, ex: -100 MZN, significa falta dinheiro. Alerta vermelho.
- Se diferença positiva, significa sobrou dinheiro. Alerta amarelo.
- Fechamento fica registrado por data, collector, valores.

FUNCIONALIDADE 3.2: DETECÇÃO DE QUEBRA DE CAIXA
Escopo: Alertar organizador sobre problemas.
Detalhes:
- Se diferença > valor configurado, ex: 1000 MZN, notificar organizador na hora.
- Se collector fecha 3 dias seguidos com diferença, notificar organizador "Risco de fraude".
- Se collector não faz fechamento por 2 dias, notificar "Inatividade".
- Organizador vê dashboard com todos collectors e status de cada um.

FUNCIONALIDADE 3.3: RELATÓRIO DE DIFERENÇA DE CAIXA
Escopo: Organizador audita collectors.
Detalhes:
- Tabela por período mostrando: Collector | Data | Sistema | Declarado | Diferença | Status
- Filtros: por collector, por data, só diferenças.
- Exportar para Excel/PDF.
- Gráfico de linha mostrando evolução da diferença por collector ao longo do mês.

MÓDULO 4: COMISSÃO E SAQUE
--------------------------------------------------------------------------------

FUNCIONALIDADE 4.1: CÁLCULO AUTOMÁTICO DE COMISSÃO
Escopo: Dia 1 de cada ciclo é da organização automaticamente.
Detalhes:
- Quando cliente completa 30 dias e paga tudo, sistema marca dia 1 como "Comissão".
- Valor da comissão = taxa_diaria x 1 dia.
- Esse valor não vai para saque do cliente, fica para organizador.
- Organizador vê total de comissão do mês: soma de todas comissões de todos clientes.

FUNCIONALIDADE 4.2: SAQUE TOTAL DO CICLO
Escopo: Cliente retira dinheiro poupado ao fechar 30 dias.
Detalhes:
- Condição: 30 dias marcados como pagos.
- Valor liberado = taxa_diaria x 29 dias. Dia 1 já foi para comissão.
- Organizador aprova saque no sistema.
- Sistema registra: data saque, valor, quem aprovou.
- Após saque, ciclo fecha e pode abrir novo para próximo mês.

FUNCIONALIDADE 4.3: SAQUE ANTECIPADO COM MULTA
Escopo: Cliente precisa dinheiro antes de fechar 30 dias.
Detalhes:
- Organizador pode autorizar saque antes dos 30 dias.
- Multa aplicada: cliente perde valor equivalente a 1 dia.
- Cálculo: valor = (dias_pagos - 1) x taxa_diaria.
- Ex: pagou 18 dias de 500 MZN, saca 17 x 500 = 8.500 MZN, perde 500 MZN.
- Sistema registra motivo do saque antecipado.
- Ciclo fecha mesmo incompleto.

MÓDULO 5: EMPRÉSTIMOS E DÍVIDAS
--------------------------------------------------------------------------------

FUNCIONALIDADE 5.1: SOLICITAÇÃO DE EMPRÉSTIMO
Escopo: Cliente pede dinheiro emprestado ao grupo.
Detalhes:
- NÃO EXISTE mínimo de dias necessários. Cliente com 0 dias pode pedir se organizador quiser.
- Cliente ou collector registra pedido: valor solicitado.
- Sistema mostra para organizador: nome cliente, dias pagos no ciclo atual, total poupado, dívida existente, histórico.
- Organizador decide aprovar ou rejeitar.

FUNCIONALIDADE 5.2: APROVAÇÃO DE EMPRÉSTIMO
Escopo: Organizador libera dinheiro.
Detalhes:
- Organizador define valor aprovado, pode ser menor que solicitado.
- Sistema calcula automaticamente juros: 10% fixo sobre valor aprovado.
- Valor total da dívida = valor_aprovado + juros.
- Ex: aprovou 2.000 MZN, dívida vira 2.200 MZN.
- Sistema registra: quem aprovou, quando, valor.
- Valor emprestado sai do caixa geral da organização.
- Organizador vê total emprestado no mês no dashboard.

FUNCIONALIDADE 5.3: GESTÃO DE DÍVIDA
Escopo: Controlar pagamento de empréstimo.
Detalhes:
- Dívida fica registrada no perfil do cliente.
- Cliente vê no app: "Dívida: 2.300 MZN" em banner vermelho.
- Pagamento pode ser total ou parcial. Collector marca pagamento.
- Sistema abate do total da dívida.
- Se não quitou até fim do mês, dívida vai para mês seguinte.
- Dívida mês seguinte = dívida anterior + juros antigos + (taxa_diaria x 30) do novo mês.
- Cliente não consegue sacar ciclo novo enquanto tiver dívida.

FUNCIONALIDADE 5.4: RELATÓRIO DE EMPRÉSTIMOS
Escopo: Organizador controla risco.
Detalhes:
- Lista todos empréstimos: Cliente | Valor | Juros | Total | Status | Data
- Filtros: pendentes, pagos, vencidos.
- Totalizadores: Total emprestado, Total juros a receber, Total inadimplente.
- Lista devedores: clientes com dívida > 0, ordenado por valor.
- Exportar para Excel.

MÓDULO 6: SINCRONIZAÇÃO OFFLINE
--------------------------------------------------------------------------------

FUNCIONALIDADE 6.1: FUNCIONAMENTO OFFLINE
Escopo: App funciona 100% sem internet.
Detalhes:
- Collector baixa lista de clientes quando tem rede.
- Marca X, faz fechamento, cadastra cliente, tudo offline.
- Dados ficam guardados no celular com segurança.
- Interface mostra "Offline - 8 pendentes" quando sem rede.
- Marcação de X é instantânea mesmo offline, sem tela de loading.

FUNCIONALIDADE 6.2: SINCRONIZAÇÃO AUTOMÁTICA
Escopo: Quando volta internet, tudo sobe sozinho.
Detalhes:
- App detecta rede e envia fila de transações em background.
- Mostra progresso: "Sincronizando 8 de 12...".
- Quando termina: "8 depósitos sincronizados" + check verde.
- Se desligar celular no meio, não perde dados. Continua depois.
- Cada transação carimba: marcado_em = hora real, sincronizado_em = hora que subiu.

FUNCIONALIDADE 6.3: RESOLUÇÃO DE CONFLITOS
Escopo: Tratar quando 2 collectors mexem no mesmo cliente offline.
Detalhes:
- Regra: Última modificação vence baseado em marcado_em.
- Se collector A marcou dia 10 às 14:00 offline, collector B marcou às 14:05 offline, vale B.
- Sistema registra conflito em log para organizador revisar.
- Organizador pode manualmente escolher qual versão manter se discordar.

MÓDULO 9: AUDITORIA E SEGURANÇA
--------------------------------------------------------------------------------

FUNCIONALIDADE 9.1: TRILHA DE AUDITORIA COMPLETA
Escopo: Nada se perde, tudo fica registrado.
Detalhes:
- Toda ação grava log: quem fez, o que fez, quando fez, de onde fez IP, qual dispositivo
- Ações logadas: login, marcar X, reverter X, fechar dia, aprovar empréstimo, alterar cliente, deletar
- Log guarda: dados antes da mudança, dados depois da mudança
- Log é imutável: não pode editar nem apagar, só adicionar
- Organizador e auditor consultam log completo

FUNCIONALIDADE 9.2: CONTROLE ONLINE VS OFFLINE
Escopo: Saber se transação foi feita com ou sem internet.
Detalhes:
- Cada depósito salva flag: modo = online ou offline
- Salva timestamp_sync: hora que realmente chegou no servidor
- Relatório filtra: "Mostrar só transações offline do Collector João dia 15"
- Ajuda detectar se alguém inventou depósitos offline

FUNCIONALIDADE 9.3: ASSINATURA DIGITAL DE TRANSAÇÕES
Escopo: Garantir que histórico não foi alterado.
Detalhes:
- Cada transação gera código hash único baseado em: ID + valor + timestamp + hash anterior
- Forma corrente: se alguém alterar transação do meio, quebra hash de todas seguintes
- Export PDF mostra hash no rodapé para validação

FUNCIONALIDADE 9.4: PERFIL AUDITOR
Escopo: Fiscalização externa.
Detalhes:
- Organizador convida auditor por email com período de acesso, ex: 01/05 a 31/05
- Auditor entra e vê tudo: dashboard, relatórios, extratos, logs
- Auditor NÃO vê botões: Aprovar, Editar, Deletar, Reverter. Só leitura
- Auditor pode exportar PDF assinado digitalmente para prestação de contas
- Após período, acesso expira automaticamente

MÓDULO 10: CONFIGURAÇÕES E PERSONALIZAÇÃO
--------------------------------------------------------------------------------

FUNCIONALIDADE 10.1: CONFIGURAÇÕES DA ORGANIZAÇÃO
Escopo: Cada grupo customiza regras.
Detalhes:
- Nome do grupo e logo
- Limite de dias retroativos: slider 1 a 30 dias, padrão 7
- Taxa de juros padrão: input %, padrão 10%
- Valor de alerta de quebra de caixa: input MZN
- Ativar/desativar módulos: Empréstimo, Transporte de dias, Foto comprovante

FUNCIONALIDADE 10.2: GESTÃO DE COLLECTORS
Escopo: Organizador controla equipe.
Detalhes:
- Cadastrar collector: nome, telefone, foto
- Atribuir clientes a collector: lista drag-drop ou seleção múltipla
- Desativar collector: bloqueia acesso mas mantém histórico
- Transferir clientes: ao desativar collector, mover todos clientes para outro
- Ver performance: volume arrecadado, % diferença, retroativos

FUNCIONALIDADE 10.3: MULTI-ORGANIZAÇÃO
Escopo: Usuário participa de vários grupos.
Detalhes:
- Um collector pode trabalhar para 3 organizações diferentes
- App mostra seletor: "Xitique Central | Xitique Norte | Xitique Sul"
- Dados totalmente separados por organização
- Login único, troca de contexto

--------------------------------------------------------------------------------

FUNCIONALIDADE 11.1: EXPORTAR PARA EXCEL

FUNCIONALIDADE 11.2: EXPORTAR PARA PDF

Detalhes:

FUNCIONALIDADE 11.3: WEBHOOKS PARA INTEGRAÇÃO
Escopo: Conectar com outros sistemas.
Detalhes:
- Organizador cadastra URL do seu sistema
- Escolhe eventos: ciclo.fechado, emprestimo.aprovado, fechamento.realizado, diferenca.detectada

FUNCIONALIDADE 11.4: INTEGRAÇÃO M-PESA FUTURA
Escopo: Reconciliação automática de depósitos.
Detalhes:

- Sistema busca depósito pendente com mesmo telefone+valor, marca pago automático
- Lista transações não reconciliadas para conferência manual

FUNCIONALIDADE DETALHADA: MARCAÇÃO DE DEPÓSITO COM CONTEXTO COMPLETO
Quando collector marca X no dia 10 de Maio para cliente Maria:
1. Sistema valida: collector está atribuído à Maria? Se não, bloqueia.
2. Sistema valida: dia 10 é <= hoje? Se futuro, bloqueia.
3. Sistema valida: dia 10 já está marcado? Se sim, retorna erro "Já pago".
4. Se passou validações, cria registro com: client_id, cycle_id, dia=10, valor=taxa_diaria_do_ciclo, collector_id, marcado_em=timestamp_agora, modo=online_ou_offline, ip=ip_conexao, device_id=id_celular, retroativo=se_data_marcada_<_hoje, motivo_retroativo=se_retroativo.
5. Se offline, marcado_em = hora do celular, sincronizado_em = null até sync.
6. Atualiza contador cycle.dias_pagos += 1.
7. Recalcula cycle.total_poupado = dias_pagos * taxa_diaria.
8. Dispara evento para notificar organizador se for retroativo.
9. Retorna sucesso com dados do dia marcado.

FUNCIONALIDADE DETALHADA: FECHAMENTO DIÁRIO COM VALIDAÇÃO DE DIFERENÇA
Quando collector fecha dia 15/05 informando 12.500 MZN:
1. Sistema busca todos deposits do collector dia 15/05 com status=X.
2. Para cada deposit, pega taxa_diaria do cycle correspondente.
3. Soma: total_sistema = SUM(taxa_diaria).
4. Calcula diferenca = 12.500 - total_sistema.
5. Salva closure: collector_id, data=15/05, valor_contabilizado=12500, total_sistema=calculado, diferenca=calculada.
6. Se diferenca != 0, cria alerta na tabela alertas.
7. Se diferenca < -1000 OU count(dias_com_diferenca_ultimos_7) >= 3, notifica organizador push.
8. Marca todos deposits do dia como "fechado" para não recontar.
9. Atualiza dashboard organizador em tempo real.

FUNCIONALIDADE DETALHADA: CÁLCULO DE COMISSÃO AUTOMÁTICA
Quando ciclo fecha 30 dias:
1. Job diário verifica cycles com dias_pagos=30 e status!=fechado.
2. Para cada, busca deposit do dia=1.
3. Atualiza deposit.dia=1 para status=P e flag comissao=true.
4. Calcula valor_comissao = cycle.taxa_diaria.
5. Insere registro em comissoes: org_id, cycle_id, valor, data.
6. Atualiza cycle.status=fechado, cycle.data_fechamento=hoje.
7. Notifica organizador: "Ciclo Maria fechado. Comissão: 500 MZN".
8. Libera saque para cliente de: (29 * taxa_diaria).

FUNCIONALIDADE DETALHADA: EMPRÉSTIMO COM CÁLCULO DE JUROS E DÍVIDA ACUMULADA
Quando organizador aprova 2.000 MZN para cliente:
1. Valida: cliente tem ciclo ativo? Se não, cria.
2. Calcula juros = 2.000 * 0.10 = 200 MZN.
3. Calcula total_divida = 2.000 + 200 = 2.200 MZN.
4. Insere loan: client_id, valor_solicitado, valor_aprovado=2000, juros=200, valor_total=2200, status=aprovado, aprovado_por=user_id, aprovado_em=agora.
5. Atualiza client.divida_total += 2200.
6. Debita do caixa_org: caixa -= 2000.
7. Se mês virar e divida_total > 0, job mensal executa:
   nova_divida = divida_total + (taxa_diaria * 30)
   Exemplo: devia 2.200, taxa 500, nova dívida = 2.200 + 15.000 = 17.200 MZN.
8. Notifica cliente: "Empréstimo aprovado: 2.000 MZN. Total a pagar: 2.200 MZN".

FUNCIONALIDADE DETALHADA: TRANSPORTE DE DIAS ENTRE MESES
Quando organizador fecha Maio com 18 dias pagos e escolhe transportar:
1. Valida: dias_pagos < 30.
2. Cria cycle Junho para cliente.
3. Marca dias 1 a 18 de Junho como status=X, collector_id=null, marcado_em=agora, flag transportado=true, ref_ciclo_anterior=id_maio.
4. Atualiza cycle_junho.dias_pagos=18, total_poupado=18*taxa.
5. Cliente agora precisa pagar só dias 19 a 30 para fechar Junho.
6. Fecha cycle_maio com status=transportado, nao aplica multa.
7. Log: "18 dias transportados de 05/2026 para 06/2026 por organizador João".

FUNCIONALIDADE DETALHADA: DETECÇÃO DE LANÇAMENTO RETROATIVO SUSPEITO
Toda vez que deposit é marcado com data_marcada < hoje:
1. Calcula dias_diferenca = hoje - data_marcada.
2. Se dias_diferenca >= 3, campo motivo_retroativo torna-se obrigatório.
3. Salva deposit com flag retroativo=true.
4. Job diário conta: quantos retroativos collector fez últimos 7 dias.
5. Se count >= 3, insere alerta: tipo=retroativo_suspeito, collector_id, quantidade, periodo.
6. Notifica organizador: "João fez 4 lançamentos retroativos esta semana. Verificar."
7. Relatório retroativos mostra: Data Real que marcou | Data do Depósito | Dias Diferença | Motivo | Cliente

FUNCIONALIDADE DETALHADA: REVERSÃO COM JANELA DE TEMPO
Quando collector tenta reverter X marcado há 30 horas:
1. Sistema calcula horas_decorridas = agora - deposit.marcado_em.
2. Se horas_decorridas > 24 E user.perfil=collector, bloqueia: "Prazo 24h expirado. Fale com organizador".
3. Se organizador ou dentro 24h, abre modal motivo obrigatório.
4. Ao confirmar, update deposit: status=O, revertido=true, revertido_por=user_id, revertido_em=agora, motivo_reversao=texto.
5. Decrementa cycle.dias_pagos -= 1.
6. Recalcula cycle.total_poupado.
7. Insere audit_log com dados_antes e dados_depois.
8. Se cycle estava fechado e agora dias_pagos<30, reabre cycle.

FUNCIONALIDADE DETALHADA: SINCRONIZAÇÃO OFFLINE COM RESOLUÇÃO DE CONFLITO
Quando app sincroniza 2 depósitos offline para mesmo cliente/dia:
1. Chegam: Deposit A por Collector João marcado_em=14:00, Deposit B por Collector Maria marcado_em=14:05.
2. Sistema detecta conflito: mesmo client_id + dia + mes.
3. Aplica regra last-write-wins: mantém Deposit B porque 14:05 > 14:00.
4. Descarta Deposit A mas salva em tabela conflitos: deposit_perdedor_id, deposit_vencedor_id, resolvido_em.
5. Notifica organizador: "Conflito resolvido: Dia 10 Maria. Mantido lançamento Maria 14:05."
6. Organizador pode abrir tela conflitos e reverter decisão manualmente.

FUNCIONALIDADE DETALHADA: CÁLCULO DE DÍVIDA COM MÚLTIPLOS MESES
Cliente pegou 2.000 em Janeiro, não pagou. Fevereiro taxa 500:
Janeiro: dívida = 2.000 + 200 = 2.200. Não pagou.
Fevereiro: nova_dívida = 2.200 + (500*30) = 2.200 + 15.000 = 17.200.
Março: se ainda não pagou, nova_dívida = 17.200 + 15.000 = 32.200.
Sistema sempre soma: dívida_acumulada + (taxa_diaria * 30) todo virar mês.
Se cliente paga 5.000 em Março: divida_total = 32.200 - 5.000 = 27.200 restante.

FUNCIONALIDADE DETALHADA: DASHBOARD COM CÁLCULOS EM TEMPO REAL
Ao abrir dashboard organizador:
1. Arrecadado Mês = SUM(deposits WHERE mes=atual AND status=X) * taxa_diaria_cada
2. Comissão Mês = COUNT(cycles WHERE status=fechado AND mes=atual) * taxa_diaria_cada
3. Emprestado Mês = SUM(loans WHERE status=aprovado AND mes=atual) valor_aprovado
4. Diferença Caixa = SUM(closures WHERE mes=atual) diferenca
5. Gráfico arrecadação = GROUP BY data, SUM valor por dia últimos 30 dias
6. Top Collectors = GROUP BY collector_id, SUM valor, ORDER DESC LIMIT 5
7. Inadimplência = COUNT(clients WHERE divida_total>0) / COUNT(clients) * 100

FUNCIONALIDADE DETALHADA: TRILHA DE AUDITORIA IMUTÁVEL
Para cada ação no sistema:
1. Antes de UPDATE deposits, trigger copia linha inteira para audit_log.dados_antes.
2. Após UPDATE, copia linha nova para audit_log.dados_depois.
3. Grava: user_id que fez, acao=UPDATE, entidade=deposits, entidade_id=id, ip, user_agent, timestamp.
4. Tabela audit_log tem trigger que bloqueia UPDATE e DELETE. Só INSERT permitido.
5. Consulta: SELECT * FROM audit_log WHERE entidade_id=123 mostra histórico completo do deposit 123.

FUNCIONALIDADE DETALHADA: NOTIFICAÇÃO MOTIVACIONAL PERSONALIZADA
Job diário 8h para cada ticante:
1. Busca cycle atual do cliente.
2. Calcula dias_pagos, total_poupado, faltam_dias = 30 - dias_pagos, faltam_valor = faltam_dias * taxa_diaria.
3. Monta mensagem: "Bom dia, {nome}! 💪 Hoje é dia de somar +{taxa_diaria} MZN. Já vai em {total_poupado} MZN! Faltam {faltam_valor} MZN."
4. Se dias_pagos % 5 == 0, adiciona: "🔥 {dias_pagos} dias seguidos! Faltam só {faltam_dias}."
5. Se hoje=30 e dias_pagos=30, mensagem: "🎉 Meta batida! {total} MZN guardados. Que tal aumentar para {taxa+100} MZN/dia próximo mês?"
6. Envia via FCM para device_ids do cliente.
